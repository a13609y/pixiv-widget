# Pixiv 每日美图小组件 v4

Egern 小组件，单一图源：**Pixiv 免登录搜索 + 反代图床**，只取全年龄作品。

## 组成

模块里有两个脚本，各管一件事：

| 脚本 | 类型 | 作用 |
| --- | --- | --- |
| `pixiv-cookie.js` | `http_request` | 你正常用 Safari 浏览 pixiv.net 时，后台从请求头 Cookie 里静默提取 `PHPSESSID`，验证是登录态后存起来并发一条通知 |
| `setu.js` | `generic` | 小组件本体：搜索、选图、缓存、渲染 |

抓到登录态后，小组件会自动解锁**热门搜索词轮换**；没抓到就照旧走免登录标签搜索，行为不变。

## 安装

```
https://raw.githubusercontent.com/a13609y/1/main/egern/setu.yaml
```

Egern → 工具 → 模块 → `+` → 粘贴地址 → 保存 → 编辑模块填 Env。
桌面长按 → `+` → Egern → 选尺寸 → 长按小组件 → 编辑 → 选「每日美图」。

### 让自动抓 Cookie 生效（可选）

1. 模块自带 `mitm.hostnames: [www.pixiv.net, accounts.pixiv.net]`，导入后不用再改
2. Egern → 设置 → 证书：生成并安装描述文件，再到 iOS「设置 → 通用 → 关于本机 → 证书信任设置」里打开开关
3. 确认 Egern 正在接管流量（代理开关打开）
4. Safari 打开 `pixiv.net`，登录一次，随便点两下
5. 几秒内会弹通知：**「Pixiv 登录态已接管」**
6. 下次小组件刷新就会用上登录态

如果弹的是「Pixiv Cookie 已更新（游客态）」，说明你还没登录，或者登录页面走的是 `accounts.pixiv.net` 但 MITM 没覆盖到——检查证书信任即可。

> 抓包脚本只**读**请求头，不改写、不阻断任何流量；会话 ID 存在 Egern 本地存储，不会外发。

本地脚本方式：工具 → 脚本 → `+`，类型 `generic`，文件名 `setu.js`，粘入内容，再到 分析 → 小组件 里绑定，Env 写在小组件的环境变量里。

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `KEYWORD` | 空 | 搜索词，标签模糊匹配 |
| `TAGS` | 空 | 标签，`\|` 或 `,` 分隔，**第一个**作为搜索词 |
| `PIXIV_WORD` | 空 | 专用搜索词，优先级最高（含空格的词写这里） |
| `WORD_MODE` | `s_tag` | `s_tag` 标签模糊 / `s_tag_full` 标签精确 / `s_tc` 标题简介 |
| `ORDER` | `date_d` | `date_d` 最新 / `popular_d` 热门（免登录会退化成最新） |
| `TYPE` | `illust` | `illust` 只要插画（默认）/ `manga` 只要漫画 / `all` 两者都要（动图一律跳过） |
| `MAX_PAGE` | `3` | 游标最多翻到第几页就回卷。页数越大作品越旧，详见下面「会不会重复」 |
| `TRENDING` | `auto` | `auto` 抓到登录 Cookie 就跟随热门搜索词；`on` 强制/`off` 关闭 |
| `PIXIV_COOKIE` | 空 | 手动填 `PHPSESSID`（不填则用自动抓取的值，一般不需要） |
| `EXCLUDE_TAGS` | 空 | 排除标签，`\|` 或 `,` 分隔，**不区分大小写的包含匹配**，命中任意一个就跳过 |
| `AI_MODE` | `any` | `any` 不筛 / `only` **只要 AI 生成** / `exclude` 过滤掉 AI |
| `COOLDOWN` | `30` | 每张图展示时长（分钟），`0` = 每次刷新换图 |
| `MAX_HISTORY` | `120` | 本地去重条数 1~500 |
| `IMAGE_QUALITY` | `auto` | `auto`：小号用 540 方图（约 40KB），中大号用 1200（约 300KB~1.2MB）；也可强制 `master` / `thumb` |
| `IMG_HOST` | `i.pixiv.re` | 图床：`i.pixiv.re`（默认）/ `i.pixiv.cat` |
| `ASPECT_FIT` | `auto` | `off` = 纯随机不挑画幅 |
| `SHOW_INFO` | `true` | 图上叠加标题（中/大号还带作者） |
| `DEBUG` | `false` | 图左下角显示 `ar 1.55/2.1 · in · p1`（画幅/是否放宽/搜索次数），排障用 |
| `TEXT_COLOR` | `#FFFFFF` | 叠加文字颜色 |
| `REQUEST_TIMEOUT` | `15` | 单次请求超时（秒）5~60 |

示例：

```
KEYWORD=DeepSeek
COOLDOWN=30
IMAGE_QUALITY=auto
```

精确标签（Pixiv 原始写法，日文优先）：

```
TAGS=ブルーアーカイブ
WORD_MODE=s_tag_full
```

## 只要插画，不要漫画

`TYPE` 默认就是 `illust`，漫画（`illustType=1`）和动图（`illustType=2`）都会在解析阶段剔掉。

```
TYPE=illust   只要插画（默认）
TYPE=manga    只要漫画
TYPE=all      插画 + 漫画
```

**踩过的坑**：Pixiv 网页搜索的 `type` 查询参数实测是无效的——`type=all`、`type=illust`、`type=illust_and_ugoira`、`type=manga` 四种传法返回的 `total` 和 36 条数据完全一样（都是 31 条插画 + 5 条漫画）。所以现在固定发 `type=all`，真正的过滤在本地按每条的 `illustType` 做。

实测 `ブルーアーカイブ` 一页：

```
过滤前  36 条（31 插画 + 5 漫画）
过滤后  31 条，池里 illustType 只有 [0]
```

代价是每页少约 14% 的候选，池子略微变小，不影响其它逻辑。

## 热门搜索（需要登录态）

抓到登录 Cookie 后，`TRENDING=auto` 会自动生效：

1. 候选池需要补货时，先请求 `/ajax/search/trending/tags?lang=zh`（登录态才给数据）
2. 从返回的热搜词里**随机挑一个**当搜索词
3. 结果缓存 6 小时，不会每次刷新都请求
4. 你自己填了 `KEYWORD` / `TAGS` / `PIXIV_WORD` 时，**显式配置优先**，热门不会覆盖

`DEBUG=true` 时角标会显示来源：`word 初音ミク · trending`，说明这次用的是热搜词；显示 `config` 说明用的是你自己填的；`default` 说明没有登录态，退回了兜底词。

> 排行榜（`/ranking.php`）在登录态下应该也能用，但我没有真实账号验证过返回结构，所以**没有接入**，避免上线一个没测过的解析。

## 排除指定标签

```
EXCLUDE_TAGS=漫画|原创|BL
```

- 多个用 `|` 或 `,` 分隔，最多 20 个
- 匹配的是作品标签（`tags` 数组），**不区分大小写的包含匹配**：写 `漫画` 会同时排掉 `漫画`、`オリジナル漫画`、`4コマ漫画`
- 命中任意一个就整张跳过，在搜索解析阶段就过滤掉，不会进候选池
- 改这个值会让候选池作废重搜（签名里包含它）
- 整页都被排掉时会自动往后翻 1 页再试，还是没有才报「这一页的作品都被 EXCLUDE_TAGS 排掉了」

实测（一页 3 条：`[漫画]`、`[イラスト]`、`[R-18G]`）：

```
EXCLUDE_TAGS=漫画|R-18G      -> 只剩 [イラスト]，池里 1 条
不填                          -> 池里 3 条
EXCLUDE_TAGS=イラスト|漫画|R-18G -> 第 1 页空，翻第 2 页也空，报错说明
```

注意：只匹配标签，不匹配标题和作者名。想连标题一起排的话告诉我，加个 `EXCLUDE_WORDS` 就行。

## 只要 AI 生成的图

Pixiv 搜索每条结果都带 `aiType`：`2` = 投稿者标注「AI 生成」，`1` = 非 AI 或未标注。

```
AI_MODE=only     只要 AI 作品
AI_MODE=exclude  过滤掉 AI
AI_MODE=any      不筛（默认）
```

实测同一页 36 条的 AI 占比：

| 标签 | aiType=2 占比 |
|---|---|
| `AIイラスト` | 36/36（100%） |
| `DeepSeek` | 32/36 |
| `ブルーアーカイブ` | 11/36 |

所以想稳定拿到 AI 图，标签最好直接选 AI 向的（`AIイラスト`、`aigc`、`AI-generated`）。用大标签（如 `ブルーアーカイブ`）+ `AI_MODE=only` 也能筛出来，只是每页只有十来张，池子消耗快一点。

注意两点：

1. **靠投稿者自觉标注**。作者上传时没勾「AI 生成」，这里就筛不到，或者反过来漏标成非 AI。这是 Pixiv 的数据，脚本无法二次判定。
2. `AI_MODE=only` 时如果某一页筛完是 0 张，脚本会自动往后多翻 **1 页**碰运气（单次换图最多 2 次请求），再没有才报「这一页没有 AI 作品，换个更 AI 向的标签」。

## 画幅匹配

搜索返回带 `width` / `height`，按「档位」挑，前一档有货就不看后一档：

| 尺寸 | 第一档 | 第二档 | 兜底 |
| --- | --- | --- | --- |
| `systemMedium` / `systemExtraLarge` | 横图 `ar ≥ 1.4` | 方图/近方图 `0.85 ~ 1.4` | 最接近的 |
| `systemSmall` / `systemLarge` | 方图 `0.8 ~ 1.25` | 近方 `0.62 ~ 1.45` | 最接近的 |

为什么中号宁可要方图也不要竖图——按 cover 填充算「能看到多少画面」（`min(原比, 框比) / max(...)`）：

| 原图比例 | 放进中号（2.1）能看到 | 放进小号（1.0）能看到 |
| --- | --- | --- |
| 1.9 横图 | 90% | 53% |
| 1.0 方图 | **48%** | **100%** |
| 0.71 竖图 | 34% | 71% |
| 0.6 极端竖图 | 29% | 60% |

所以中号：横图 90% 显然最好；没有横图时方图 48% 也比竖图 34% 强得多。小号反过来，方图 100% 最优。

同一档内再按 `|ln(比例/目标)|` 最接近的 3 张里随机。`DEBUG=true` 时角上会显示档位：`in` 第一档 / `near` 第二档 / `relaxed` 兜底。

**取不到第一档就换页，不硬塞。** 横图在 Pixiv 里是少数，实测一页 36 条里只有：

| 标签 | 横图数（≥1.4） |
| --- | --- |
| `ブルーアーカイブ` | 6 / 36 |
| `オリジナル` | 4 / 36 |
| `オリジナル` + `AI_MODE=only` | 0 / 36 |

中号/超大号如果当前池里没有横图，会继续往后翻页补货（同一次刷新最多再搜 2 页），还是找不到就落到第二档方图；两页都没货会记一个 6 小时标记，这段时间不再为画幅白翻页（池子空了该搜还是照搜）。

## 会不会重复 / 会不会越翻越旧

`ORDER=date_d` 下页码和作品年龄是绑定的：第 p 页装的是「第 (p-1)×36+1 到 p×36 新」的作品。所以游标往后翻 = 看更旧的作品。

实测两个标签（一次请求就能算出来，因为每条结果都带 `createDate`）：

| 标签 | 收录量 | 上架速度 | 第 1 页覆盖 |
| --- | --- | --- | --- |
| `DeepSeek` | 805 | ≈ 28 张/天 | 31.2 小时 |
| `ブルーアーカイブ` | 551,182 | ≈ 275 张/天 | 3.1 小时 |

也就是说：

- **热门标签**第 1 页每 3 小时就整体换代，冷门标签要 31 小时
- 不加限制地一直往后翻，第 10 页的热门标签就是十几天前的作品了 —— 所以加了 `MAX_PAGE=3`，游标 `1 → 2 → 3 → 1` 循环，只在最前面几页打转
- 回卷到第 1 页时，距离上次看第 1 页已经过了 3 轮（约 1.5 天），热门标签早换了十几轮、冷门标签也换了 1 轮多，**基本不会重复**
- 真重复了还有 `history`（默认 120 条，≈ 3.3 页）兜底，比对的是图片 URL，重复的直接跳过换下一张
- 极端情况（标签只有几十张作品，历史把整页都覆盖了）会强制重复，但同一轮里只发一次搜索，不会死循环

## 请求量

| 场景 | 请求数 |
| --- | --- |
| 冷却期内刷新 | **0** |
| 换一张图（池里还有货） | 1（仅图片） |
| 换一张图（池子空了） | 1 搜索 + 1 图片 |
| 一次搜索可支撑 | 36 张 × COOLDOWN（默认 30 分钟 ≈ 18 小时） |
| 池子闲置 12 小时 | 作废重来（只要还在取用就自动续期，不会用一半被丢） |
| 命中 403 / 429 | 不重试，用缓存，下次刷新推迟 45 分钟 |

搜到的 36 条元数据存本地池 `sx5_pool`，去重历史 `sx5_history`，图片与时间戳按尺寸分别缓存（`sx5_cache_*` / `sx5_lastshow_*`）。改搜索参数会自动作废候选池（签名比对），不会拿旧关键词的结果凑数。

## 实测记录

- **搜索**：`GET https://www.pixiv.net/ajax/search/artworks/{word}?word=..&order=date_d&mode=safe&p=1&s_mode=s_tag&type=all&lang=zh` 免 cookie 返回 `200`，`body.illustManga.data` 36 条，含 `id / width / height / tags / userName / illustType / pageCount / url`，翻页正常。`DeepSeek` 标签 total 803。
- **图片**：`i.pixiv.re` 与 `i.pixiv.cat` 都能取 `/img-master/..._master1200.jpg`；缩略只白名单 `c/360` 与 `c/540`，`c/720` 以上返回 `403`。`pixiv.cat/{id}.png` 只给原图（实测 8.7MB），不适合小组件，所以走反代路径改写。
- **自定义缩略图**：约 1/4 的作品搜索结果给的是 `/custom-thumb/..._custom1200.jpg` 路径，最初版本推不出高清地址会退回这张 23KB 的小图（糊）。已修正为把 `/custom-thumb/` 归一成 `/img-master/`，实测同一作品由 23KB 变 1087KB 的 `_master1200.jpg`。
- **三种尺寸实跑**：中号 `ar=1.77`（横图，896KB）、小号 `ar=1.00`（方图，58KB）、大号 `ar=1.00`（1200，1222KB），三次刷新总共 1 次搜索。

## 已知限制

- 热门搜索词依赖登录态；Cookie 失效（重新登录/强制下线）后会退回避难所模式，重新浏览一次 pixiv.net 即可再次捕获

- Pixiv 搜索是网页内部接口，不是公开契约，参数与风控随时可能变。已做 403/429 识别、退避、缓存兜底，但不保证长期有效。
- 只搜全年龄内容（`mode=safe`），这是刻意固定死的，没有开关。
- 图床没有 720/1080 档，中/大号只能在「高清但几百 KB~1MB」和「40KB 但会被裁成方图」之间二选一，默认取高清。
- 刷新时机由 WidgetKit 决定，`refreshAfter` 只是建议值。
- 未在 Egern 真机渲染验证，只做了语法静态校验 + 真实接口链路测试。
